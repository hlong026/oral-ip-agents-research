# 管理控制台功能补全工作单

> 立项依据：管理页面综合业务分析（2026-07）。对标同类 AI 数字人视频 SaaS（HeyGen、闪剪、来画、硅基智能）后台能力，结合本项目「激活码制会员 + 积分经济 + AI 视频生产流水线」特点，识别功能缺口并排期补全。
> 前序工作单：`docs/ADMIN-UI-OPTIMIZATION.md`（后台设计优化，已完成 Phase 1/2）。

| 系统配置 | Provider 配置 | 供应商密钥、探活、就绪度 |

### 核心缺口（本工作单范围）

1. **资金正确性断层**：对账接口后端已实现（`/api/admin/v1/reconciliations`），前端无任何页面接入，冻结积分无人可在界面处理
2. **客服支撑域为零**：无用户 360 视图、无全局任务运维台，客诉无从查起
3. **合规审查域缺失**：声音/数字人克隆仅靠用户端勾选授权，无管理端审查、留档、下架能力（深度合成强监管点）
4. **可观测域薄弱**：激活码风控事件、供应商配额水位不可见——项目历史上多次因「静默失败」产生客诉

---

## 🎯 目标与原则

1. **先接现成接口，再造新接口**：P0 中对账工作台后端零改动，只补前端
2. **客服可独立闭环**：用户问题从「查」到「处置」全部在管理端完成，不依赖开发人员查库
3. **合规留痕**：所有资金操作、授权审查、人工裁决必须写审计日志并强制填写原因
4. 沿用既有规范：表单最小必填 + 渐进式披露、配置项全中文化、lucide-react 图标、侧边栏四组结构

## ✅ 工作项明细

### 【P0-1】对账工作台（后端现成，仅前端）

**背景**：外部供应商（飞影等）非幂等提交结果未知时，任务/声音/分身进入 `reconciliation_required` 状态并保持积分冻结，需管理员凭供应商后台证据人工裁决。接口已实现，无 UI。

**现有接口**（零后端改动）：
- `GET /api/admin/v1/reconciliations` → `{ items: [{ kind, id, userId, name, step, reservationId, createdAt }], total }`，kind ∈ `pipeline | voice | avatar`
- `POST /api/admin/v1/reconciliations/{kind}/{record_id}`，body：`{ action: "release" | "settle" | "resume", reason: string(3-500), providerTaskId?: string }`

**前端设计**：
- 新页面 `/reconciliations`，归入侧边栏「商业化」组（图标：`Scale`）
- 列表列：类型（中文徽标：成片任务/声音克隆/数字人训练）、名称、用户、卡住步骤、冻结单号、滞留时长（超 24h 标红）
- 行内操作三按钮 + 二次确认弹窗，强制填写处置原因：
  - **恢复轮询**（resume）：需填供应商任务 ID，适用于供应商后台确认任务仍在执行
  - **结算积分**（settle）：供应商实际已扣量，冻结转实扣
  - **释放积分**（release）：供应商确认未执行，冻结退还用户
- 总览页驾驶舱顶部 KPI 行追加「待对账」数字卡，>0 时高亮预警

**验收标准**：
- 构造一条 `reconciliation_required` 记录，三种 action 均可走通且积分账变正确
- 每次裁决在「成本与审计」页可见审计记录（含原因）
- 无待办时页面展示空态而非报错

### 【P0-2】用户管理升级：搜索分页 + 用户 360 视图

**背景**：现页面全量拉取 + 下拉框选人调积分，用户过百不可用；客服无法查看单用户全貌。

**后端改动**：
- `GET /users` 已支持 `page/pageSize`（前端未传），**新增** `search` 参数（手机号/昵称/用户 ID 模糊匹配）与 `status` 筛选（active/disabled/expired）
- **新增** `GET /users/{user_id}/detail`：聚合返回——
  - 基本信息（现列表已有字段：套餐、到期、设备绑定、激活码掩码、余额）
  - 积分流水（复用 billing 模块账变记录，分页）
  - 任务历史（pipeline 最近 20 条：标题、状态、耗时、消耗积分）
  - 资产概览（声音/分身数量与状态）
  - 审计记录（该用户被管理员操作的历史）

**前端设计**：
- 列表页：搜索框 + 状态筛选 + 分页器；行点击进入详情
- 详情页 `/users/:id`：左侧信息卡（套餐/设备/激活码来源），右侧 Tab（积分流水 | 任务历史 | 资产 | 操作记录）
- 现有操作（调积分、解绑设备、禁用）移入详情页操作区，调积分强制填写原因（后端已要求 reason）

**验收标准**：
- 500 用户量级下搜索响应 < 1s，分页正确
- 详情页四个 Tab 数据与数据库一致
- 客服场景演练：凭用户手机号 3 步内定位到失败任务与对应积分扣减记录

### 【P0-3】全局任务运维台

**背景**：pipeline 模块无 admin 路由，管理端完全看不到生产任务。用户反馈「成片卡住/失败」时无法查证与干预。项目有「视频链接解析静默降级」历史教训，缺管理端可观测面。

**后端改动**（新增 `pipeline/router.py` 的 `admin_router`，挂 `/api/admin/v1`）：
- `GET /tasks`：分页 + 筛选（userId / status / step / 时间范围），返回任务级摘要
- `GET /tasks/{task_id}`：完整七步状态、步骤级产物 key、错误信息（含被 200 字截断前的完整报错，管理端可见全文）
- `POST /tasks/{task_id}/retry`：从失败步重试（复用现有 rewrite-skip 行为规范）
- `POST /tasks/{task_id}/terminate`：终止并按已完成步骤结算、未执行部分释放冻结（复用 billing release/settle）
- 全部操作走审计日志

**前端设计**：
- 新页面 `/tasks`，归入侧边栏「用户与安全」组更名为「用户与运维」（图标：`ListChecks`）
- 列表：状态徽标（运行中/失败/待确认/待对账/完成）、当前步骤、用户、耗时、消耗积分；失败任务置顶
- 详情抽屉：七步时间线（步骤状态 + 耗时 + 产物链接 + 报错全文），底部干预操作（重试/终止退费），均二次确认 + 原因必填

**验收标准**：
- 失败任务可从管理端重试并成功续跑；终止任务积分账变正确
- 报错全文可见（不受用户端 200 字截断约束）
- 干预操作全部留审计记录

### 【P0-4】克隆资产合规审查

**背景**：《深度合成管理规定》《AI 生成合成内容标识办法》要求服务提供者对克隆授权留存、可追溯、可撤销。当前仅用户端勾选「我确认拥有合法授权」，管理端无审查与下架能力。对标 HeyGen（人工审核 avatar 授权）、硅基智能（实名 + 授权双审）均为硬流程。

**后端改动**：
- **新增** `GET /clone-assets`：聚合声音 + 分身列表（用户、类型、状态、训练素材 key、创建时间、授权勾选时间）
- **新增** `POST /clone-assets/{kind}/{id}/takedown`：违规下架（资产置为 `disabled`，用户端不可再用于合成），body 强制 `reason`
- 训练素材（原始音频/视频）通过现有存储签名 URL 供管理端试听/预览
- Voice/Avatar 模型增加 `disabled_reason`、`reviewed_at`、`reviewed_by` 字段（Alembic 迁移）

**前端设计**：
- 新页面 `/clone-assets`，归入「用户与运维」组（图标：`FileCheck`）
- 列表 + 筛选（类型/状态/未审查优先），行内素材试听/预览
- 下架操作二次确认 + 原因必填；已下架资产显示原因与操作人
- 抽查工作流：默认按「未审查」排序，审查通过打标记

**验收标准**：
- 下架后用户端立即不可选用该资产发起合成（后端合成入口校验 status）
- 素材可在管理端直接预览（签名 URL 有效）
- 审查与下架记录可在审计页追溯

### 【P1-1】积分流水查询

- **新增** `GET /credits/transactions`：全局账变流水，筛选（userId / 类型：消耗、冻结、结算、释放、手工调整、激活发放 / 时间范围），分页
- 前端并入「成本与审计」页新 Tab「积分流水」；手工调整类型高亮显示操作人与原因
- 验收：与用户 360 视图流水 Tab 数据同源一致；调积分后立即可查

### 【P1-2】激活码风控可视化

- **新增** `GET /activation/risk-events`：失败尝试记录（设备指纹、IP、时间、命中码掩码）与当前锁定中的设备清单，支持手动解锁
- 前端并入「激活码批次」页新 Tab「风控监控」：24h 失败尝试趋势小图、锁定设备表、高频攻击设备指纹 Top10
- 验收：模拟 10 次失败触发锁定后，事件与锁定状态在页面可见，手动解锁生效

### 【P1-3】供应商配额水位与告警

- Provider 配置页扩展：接入 HiFly 账户余量/配额查询接口（若供应商提供），无接口则以本侧调用量估算水位
- **新增**阈值配置（如剩余 <20% 预警），触达方式首期为总览页驾驶舱红色横幅 + 管理端站内提示
- 验收：水位低于阈值时总览页出现预警横幅；探活失败与配额耗尽两种状态可区分

### 【P1-4】素材库管理（BGM / 封面模板 / 字体）

- **新增** `GET/POST/DELETE /assets/library`：按类型管理公共素材（bgm / cover_template / font），上传走现有存储驱动
- 前端新页面 `/library`，归入「系统配置」组（图标：`Library`）；BGM 可试听、封面模板可预览
- 剪辑链路（FFmpegCompose / CoverSpec）从素材库读取而非硬编码路径
- 验收：上传新 BGM 后用户端剪辑步可选用；删除素材不影响已生成成片

### 【P1-5】管理员 RBAC 最小分权

- 管理员角色扩展为三档：`super`（全部）、`finance`（价格/积分/对账）、`support`(用户/任务/克隆审查，只读商业化)
- 后端 `require_admin` 升级为 `require_admin(scope)`；JWT claim 加 `admin_scope`
- 前端侧边栏与操作按钮按 scope 隐藏；越权请求后端 403
- 验收：support 角色无法调积分与改价格；所有资金操作仅 finance/super 可见

### 【P1-6】发布渠道健康页

- 复用驾驶舱发布数据，扩展渠道维度：各平台近 7 天发布量/失败率、失败原因 Top5、平台账号授权状态与到期预警
- 前端并入总览页下钻或独立页 `/publish-health`（视数据量定，首期做总览下钻）
- 验收：单渠道失败率 >20% 时驾驶舱对应卡片标红

## 🛠️ 技术约定

1. 全部新页面沿用现有 `adminFetch` / TanStack Query / glass 卡片风格，图表继续用 ECharts
2. 新增后端接口全部挂 `/api/admin/v1`，走 `require_admin` 与审计日志；OpenAPI 快照与 `packages/types` 每次接口变更后重新生成（`pnpm gen:api`）
3. 资金相关操作（对账裁决、终止退费、调积分）后端强制 `reason` 字段，前端二次确认弹窗
4. 侧边栏调整：「用户与安全」→「用户与运维」（用户管理、任务运维、克隆审查、私信安全）；对账工作台入「商业化」；素材库入「系统配置」
