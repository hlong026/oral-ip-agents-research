# 第三阶段 S3-14 七天灰度验收

> 建立日期：2026-07-21
> 当前状态：**待运行，尚未满足生产退出门槛**

## 1. 目标与边界

S3-14 只允许管理员批准的小范围账号进入私信监听和自动回复链路。灰度账号仍需逐账号确认当前版本风险协议；全局 Kill Switch 默认停止，并始终拥有最高优先级。

法务书面授权已由项目负责人确认取得，但授权正文和账号 Cookie 不进入代码仓库。生产评审前，必须在受控文档系统补齐授权文件编号、批准范围和有效期，并同时完成第二阶段真实链路证据及 S3-03 真实收发/ACK 证据。

## 2. 进入灰度前检查

1. 数据库已迁移到最新 Alembic head，`im_gray_accounts` 和 `im_metric_events` 已存在。
2. `IM_ENABLED=true` 仅配置在经批准的灰度环境，`IM_GRAY_ENFORCED=true` 不得关闭。
3. 管理端全局 Kill Switch 保持“停止”，先加入 1–2 个内部受控账号；`IM_GRAY_MAX_ACCOUNTS` 默认受控上限为 20。
4. 每个账号已完成风险协议确认、Cookie 保管责任确认和人工接管人指定。
5. 已验证管理员能执行全局急停，移出灰度名单会停止监听、关闭自动回复并取消排队消息。
6. 监控接口、审计日志和通知通道可读取，系统时钟准确。

## 3. 每日操作

固定在每天同一时刻抓取过去 24 小时聚合指标：

```bash
cd server
export STAGE3_ADMIN_TOKEN='<临时管理端令牌>'
uv run python scripts/stage3_gray_report.py \
  --api-base 'https://<灰度域名>/api/admin/v1' \
  --output-dir '../evidence/stage3'
unset STAGE3_ADMIN_TOKEN
```

脚本只保存聚合指标，不保存 Token、Cookie、私信正文或用户标识明细。同一天重复执行会保留所有抓取记录，并按最差成功率和最高事故数生成当日汇总，避免后一次抓取覆盖早先异常。

服务端原始监控事件包含受限的账号/用户标识和错误类别，用于聚合及事故追踪，按 `IM_METRIC_RETENTION_DAYS` 默认保留 14 天；这与脚本输出的脱敏聚合证据是两个不同的数据层级。

平台出现封控、风险提示或需要人工判断的异常时，管理员应立即：

1. 执行全局急停；
2. 在“私信自动回复安全”页面登记风控事件；
3. 移出相关灰度账号并保留审计记录；
4. 完成根因修复和重新评审后，从新的连续七天观察窗口重新计时。

## 4. 指标口径与门槛

| 指标         | 口径                                                            | 每日退出门槛               |
| ------------ | --------------------------------------------------------------- | -------------------------- |
| 灰度账号     | 当前启用的 allowlist 账号                                       | 至少 1 个                  |
| 连接成功率   | `listener_connected / listener_connect_attempt`                 | 不低于 90%                 |
| 掉线率       | `(listener_disconnected + listener_error) / listener_connected` | 不高于 10%                 |
| 发送成功率   | `send_success / (send_success + send_failure)`                  | 不低于 90%                 |
| 限额拒绝     | 原子限额拒绝次数                                                | 观察项，不单独判失败       |
| 内容审核拦截 | 发送前审核阻断次数                                              | 观察项，不单独判失败       |
| 凭证失效     | 明确 Cookie 失效次数                                            | 观察项，必须确认已停止重试 |
| 消息归属拒绝 | 过期或错误账号归属被拦截次数                                    | 必须为 0                   |
| 平台风控事故 | 管理员登记的封控/风险事件                                       | 必须为 0                   |

每一天还必须至少有一次真实连接尝试和一次真实发送尝试；没有活动的“空跑”日期不能计入连续七天。

## 5. 退出判定

连续运行七天后执行：

```bash
uv run python scripts/stage3_gray_report.py \
  --api-base 'https://<灰度域名>/api/admin/v1' \
  --output-dir '../evidence/stage3' \
  --require-exit-ready
```

只有 `evidence/stage3/rollup.json` 中 `exitReady=true` 且命令退出码为 `0`，才能认定 S3-14 的七天观察项通过。日期必须连续并以执行当日结束；任一日缺失、无实际活动、低于成功率门槛、出现归属拒绝或风控事故都会失败。

即使 S3-14 通过，生产放量仍需同时满足：

- 第二阶段真实 Provider、成片、计费和真实发布证据完整；
- S3-03 设备注册、签名、WS 握手、ACK 和发送响应已用授权真实账号验证；
- 法务授权引用信息和数据责任边界已进入受控评审记录；
- 发布负责人签署最终 Go 决策。

仓库已提供灰度 allowlist、强制门禁、监控聚合、风控事件登记和七日证据工具，但时间性验收不能由代码测试替代。2026-07-21 尚无连续七天 `evidence/stage3` 产物，因此当前仍为生产 **No-Go**。
