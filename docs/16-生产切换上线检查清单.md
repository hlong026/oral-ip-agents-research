# 16 - 生产切换上线检查清单

> 配套：`server/.env.production.example`（配置基线）。目标：机制性保证生产环境零 Mock 产物，
> 任何降级到演示数据的结果要么被拒收，要么带全链路"演示数据"标记。

## 机制性防线（代码层已内置，无需人工干预）

| 防线                | 位置                                            | 行为                                                                                                                                   |
| ------------------- | ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 零 Mock 启动自检    | `app/providers/registry.py`                     | `APP_ENV=prod` 时任何链混入 `mock-` provider 立即抛异常拒绝启动                                                                        |
| Mock 开关按环境推导 | `app/core/config.py`                            | 非 dev/test 环境 `mock_fallback_allowed` 无条件 False，不受 .env 误配影响                                                              |
| Pipeline 拒收防线   | `app/modules/pipeline/engine.py`                | parse/asr/voice/avatar/compose 步收到 Mock 结果：prod 转任务失败；dev/test 打 `degraded_mock` 标记                                     |
| Content 拒收防线    | `app/modules/content/service.py`                | 链接解析/转写降级到 Mock 时拒绝落库占位文案                                                                                            |
| 生产配置强校验      | `app/core/config.py::validate_runtime_security` | 短密钥、重复密钥、占位值、SQLite、本地存储、无主机/非 HTTPS 公网地址、非正式 Web/Tauri CORS、有头浏览器及 `IM_ENABLED=true` 均拒绝启动 |
| CI 门禁             | `server/tests/test_production_no_mock.py`       | prod 注册表零 Mock、pipeline 拒收 Mock 回归单测                                                                                        |
| 依赖安全门禁        | `.github/workflows/ci.yml`                      | PyPA `pip-audit` 与 `pnpm audit --prod` 任一发现已知漏洞即失败                                                                         |
| 容器部署门禁        | `server/Dockerfile`                             | 镜像内置 Chromium、FFmpeg、真实发布驱动，以非 root 用户运行；CI 从仓库根目录实构建                                                     |

## 部署前硬门槛

- [ ] 使用 Node.js 22.22.0 或更高版本、pnpm 9.15.0、Python 3.12
- [ ] `uv lock --check --directory server`、`pnpm install --frozen-lockfile` 均通过
- [ ] `uv run --directory server --with pip-audit==2.10.0 pip-audit --local` 无已知漏洞
- [ ] `pnpm audit --prod --audit-level high` 无高危及以上漏洞
- [ ] 从仓库根目录执行 `docker build -f server/Dockerfile -t oral-ip-server:<commit> .`
- [ ] 镜像使用不可变 commit/tag；API、Worker 和迁移任务必须使用同一镜像
- [ ] 根目录 `docker-compose.yml` 只用于本地开发，禁止作为生产编排文件

## 上线六步检查

### 第 1 步：环境变量

- [ ] 复制 `server/.env.production.example` 为 `.env`，确认 `APP_ENV=prod`
- [ ] 五把密钥全部替换为互不相同的高强度随机值：`APP_SECRET` / `CONFIG_ENCRYPTION_KEY` / `ACTIVATION_SECRET` / `PUBLISH_SESSION_ENCRYPTION_KEY` / `FEIYING_WEBHOOK_SECRET`
- [ ] 所有 `REPLACE_*`、`change-me*`、`*.example.com` 占位值均已替换
- [ ] `DATABASE_URL` 使用 `postgresql+asyncpg://`，`REDIS_URL` 指向生产 Redis
- [ ] `STORAGE_DRIVER=s3`，S3/MinIO 配置真实可用，API 与 Worker 共享同一对象存储
- [ ] `MEDIA_PUBLIC_BASE_URL` 使用公网可达的正式 HTTPS 地址（云端 ASR 回源下载依赖）
- [ ] `CORS_ORIGINS` 只填写正式 HTTPS 前端域名；发布桌面端时才额外加入固定来源 `tauri://localhost`（macOS/Linux）和 `https://tauri.localhost`（Windows）
- [ ] `PUBLISH_BROWSER_HEADLESS=true`
- [ ] `IM_ENABLED=false`（合规 No-Go，开启会拒绝启动）
- [ ] 前端构建时不设置 `VITE_ANALYTICS_PREVIEW` / `VITE_ASSETS_PREVIEW`（V1.1 占位页保持隐藏）

### 第 2 步：数据库迁移

在发布 API/Worker 前，用待发布的同一镜像执行一次：

```bash
docker run --rm --env-file /secure/path/oral-prod.env oral-ip-server:<commit> alembic upgrade head
```

- [ ] 迁移任务成功退出，数据库版本只有一个 head
- [ ] 数据库已完成发布前快照，记录镜像 tag、迁移前后 revision 与执行时间
- [ ] 迁移失败时停止发布，不允许由应用 `create_all` 兜底

### 第 3 步：启动 API 与 Worker

- [ ] API 与 Dramatiq Worker 使用同一镜像、同一环境变量版本
- [ ] API 至少两个副本；迁移任务只运行一次
- [ ] `/app/storage` 不承载生产媒体真源，媒体统一进入 S3/MinIO
- [ ] 容器以 UID 10001 非 root 运行，并能执行 `chromium --version`、`ffmpeg -version`
- [ ] IM Listener 不部署；当前合规状态仍为 No-Go

### 第 4 步：供应商正式 Key

通过管理端「Provider 配置」页录入（加密落库，保存即时生效）：

- [ ] DeepSeek：API Key + 模型
- [ ] Douyidou：App ID + App Secret
- [ ] DashScope（Fun-ASR）：API Key + 地域
- [ ] 飞影：API Key（数字人 + 声音共用）

### 第 5 步：管理端开关与就绪度看板

- [ ] 管理端「Provider 配置」页四个供应商开关全部启用
- [ ] 就绪度看板（页面顶部）勾选「含连通性探测」后刷新，确认**全部就绪**
- [ ] 确认看板显示「Provider 模式：全真实链路」
- [ ] 接口核对（可选）：`GET /api/admin/v1/providers/readiness?probe=true` 返回 `allReady=true`

### 第 6 步：/readyz 部署验证

```bash
curl -s https://api.example.com/readyz | python3 -m json.tool
```

- [ ] `env` = `prod`
- [ ] `provider_mode` = `real_only`
- [ ] `mock_fallback_allowed` = `false`
- [ ] `provider_chains` 各链名单不含任何 `mock-` 前缀条目，`publish` 链为 `sau-*` 真实驱动
- [ ] `dependencies.database.ok` = `true`
- [ ] `dependencies.redis.ok` = `true`
- [ ] `dependencies.storage.ok` = `true`
- [ ] HTTP 状态码为 200；任一必需依赖失败时必须返回 503

## 切换后 E2E 冒烟（staging，真实供应商 Key）

- [ ] 链接解析 → 文案 → TTS → 数字人 → 合成 → 发布，全链路跑通一次
- [ ] 核对产物均为真实媒体文件（非 .txt 占位；视频可播放、音频可试听）
- [ ] 发布平台在 staging 用真实账号验证扫码登录 + 发布各一次，再加入 `PUBLISH_VERIFIED_PLATFORMS`
- [ ] 前端生产构建：数据看板/素材库/模板中心入口不可见，直达路由重定向工作台
- [ ] API/Worker 各重启一次，确认待处理任务、Webhook 和发布任务可恢复且不重复扣费

## 桌面端分发门禁

- [ ] 构建时显式设置 `VITE_API_BASE=https://<正式API域名>/api/v1`
- [ ] `pnpm --filter @oral/desktop check:release` 通过，确认 API、CSP、主窗口标签和 Windows HTTPS scheme 均有效
- [ ] `pnpm --filter @oral/desktop tauri:build --no-bundle` 通过，只作为工程编译证据
- [ ] macOS 使用正式 `APPLE_SIGNING_IDENTITY`，并配置 App Store Connect API 或 Apple ID 公证凭证中的一整组
- [ ] `pnpm --filter @oral/desktop check:distribution` 通过后才执行 `release:mac`
- [ ] 生成的 macOS 安装包在干净机器验证签名、公证、首次启动、登录、WebSocket 任务通知和媒体播放
- [ ] Windows 在受控 Windows CI/机器生成签名安装包，并在干净 Windows 机器验证安装、卸载和远程 API 链路
- [ ] 当前未启用 Tauri updater；在更新服务、私钥离线保管、公钥内置和回滚策略完成前，不对外承诺自动更新
- [ ] 桌面业务 API 基址已锁定为正式公网域名；不得把 localhost、内网/保留域名、测试令牌或 Provider 密钥打入前端资源
- [ ] 当前 CSP 的 `connect-src` 为支持正式 API/WSS 使用 HTTPS/WSS scheme，不是目标主机白名单；仍必须依赖固定 API 构建值、JWT、后端权限与安装包签名共同防护

## 回滚与停机条件

- [ ] 迁移、`/readyz`、真实主链或结算校验任一失败，立即停止新流量和新任务
- [ ] 应用回滚只切换到上一不可变镜像；不得继续运行新旧版本混合 Worker
- [ ] 数据库需要降级时，先停止 API/Worker、确认无运行中任务，再按发布记录执行对应 `alembic downgrade`
- [ ] 已经成功结算并生成的媒体不得因发布失败或回滚被删除
- [ ] 回滚后重新验证 `/readyz`、余额流水、任务恢复与一个最小真实链路
