# 23 - 腾讯云生产部署与回滚手册

## 1. 架构结论

生产环境使用独立 `docker-compose.prod.yml`，不得使用根目录的本地开发 Compose。生产编排只负责应用容器：Gateway、Web、Admin、API、Worker、数据库迁移任务和可选 COS 迁移任务。

以下依赖必须由生产环境单独提供：

- PostgreSQL 16：腾讯云数据库或经过备份治理的独立实例。
- Redis 7：腾讯云 Redis 或经过持久化和监控治理的独立实例。
- 腾讯云 COS：媒体真源，API 与 Worker 使用同一 Bucket。
- 腾讯云 CLB 或等价 HTTPS 入口：TLS 在可信负载均衡器终止，再转发至 Gateway 8080。
- 容器镜像仓库：Server、Gateway、Web、Admin 使用不可变 SHA-256 digest。

生产 Compose 不创建 MinIO、PostgreSQL 或 Redis，避免把开发默认密码和单机数据卷误当生产架构。

## 2. 容器职责

| 服务 | 镜像与职责 |
| --- | --- |
| gateway | 不可变非 root Nginx 镜像，按 Web/Admin 域名分流，并代理 API、媒体和 WebSocket |
| web | 用户端静态 SPA，非 root Nginx 8080 |
| admin | 管理端静态 SPA，非 root Nginx 8080 |
| server | FastAPI API、媒体签名、账号与业务接口 |
| worker | Dramatiq 异步任务、FFmpeg、Chromium 发布 |
| migration | 与 Server 同镜像，发布前只执行一次 `alembic upgrade head` |
| cos-migration | 与 Server 同镜像，按 profile 手动运行对象迁移 |

API、Worker、Migration 必须使用完全相同的 `ORAL_SERVER_IMAGE` digest，禁止新旧 Worker 混跑。Gateway 配置也属于应用版本，回滚时必须同步切回上一 Gateway digest。

## 3. 前置准备

1. 创建 Web、Admin、API 域名和 DNS。
2. CLB 配置 HTTPS 证书，并将后端转发到服务器 `127.0.0.1:18080` 对应的主机入口；若 CLB 无法访问 loopback，应把 `GATEWAY_BIND` 改为受安全组限制的内网地址。
3. 创建 `/etc/oral/oral-prod.env`，权限设置为 `0600`。
4. 创建 `/etc/oral/deploy.env`，参考 `deploy/.env.prod.example`，权限设置为 `0600`。
5. 将数据库、Redis、COS 和正式 Provider 密钥写入 `oral-prod.env`，不要写入 Compose 或 Git。
6. 确认 COS、服务器、数据库尽量位于同一腾讯云地域。
7. 为 Server/Worker CAM 子账号应用 `deploy/tencent-cos/cam-runtime-policy.template.json` 的最小权限版本。

## 4. 构建镜像

从同一 Git commit 构建四个镜像：

```bash
docker build -f server/Dockerfile -t registry.example.com/oral/server:<commit> .
docker build -f deploy/Dockerfile.gateway -t registry.example.com/oral/gateway:<commit> .
docker build -f deploy/Dockerfile.frontend --target web -t registry.example.com/oral/web:<commit> .
docker build -f deploy/Dockerfile.frontend --target admin -t registry.example.com/oral/admin:<commit> .
```

推送镜像后读取仓库返回的 digest，将部署文件中的四个镜像全部改为：

```text
registry.example.com/oral/<component>@sha256:<digest>
```

部署脚本默认拒绝普通 tag、`latest` 或长度不正确的 digest。Gateway、Web、Admin 基础镜像已在 Dockerfile 中固定 digest；生产发布镜像仍须固定为镜像仓库返回的最终 digest。

## 5. 首次部署

```bash
cp deploy/.env.prod.example /etc/oral/deploy.env
chmod 600 /etc/oral/deploy.env /etc/oral/oral-prod.env
bash deploy/scripts/deploy.sh /etc/oral/deploy.env
```

脚本固定执行顺序：

1. 校验 Compose。
2. 拉取不可变镜像。
3. 停止旧 API 和 Worker，避免迁移期间继续处理旧 Schema。
4. 使用发布 Server 镜像执行数据库迁移。
5. 启动 API、Worker、Web、Admin 和 Gateway。
6. 检查 `/readyz`，要求 `ok=true`、`env=prod`、存储为 `s3` 且可用。

迁移失败时脚本立即停止，不启动新版本容器。`ORAL_ENV_FILE` 权限必须为 `0400` 或 `0600`，否则部署脚本拒绝执行。

## 6. CLB 与 Gateway

Gateway 镜像由 `deploy/Dockerfile.gateway` 构建，配置模板已经写入镜像，不从生产服务器挂载仓库文件。运行时仅通过以下环境变量生成最终配置：

- `WEB_HOST`：用户端域名。
- `ADMIN_HOST`：管理端域名。

Gateway 会代理：

- `/api/`
- `/media/`
- `/ws/`
- `/healthz`
- `/readyz`
- `/openapi.json`

上传和媒体响应关闭 Nginx 全量缓冲，长任务超时为 900 秒。`X-Forwarded-Proto` 固定为 `https`，前提是只有可信 CLB 能访问 Gateway 端口。

安全组必须禁止公网直接访问 API、Worker、Web、Admin 的容器端口。外部只访问 CLB 的 443。Gateway 默认只绑定宿主机 loopback；需要 CLB 访问内网地址时，必须同步限制腾讯云安全组来源。

## 7. 迁移 COS 数据

执行流程见 `docs/22-腾讯云COS迁移与权限操作手册.md`。生产 Compose 已提供 `cos-migration` profile：

```bash
docker compose \
  --env-file /etc/oral/deploy.env \
  -f docker-compose.prod.yml \
  --profile cos-migration run --rm cos-migration
```

迁移状态目录必须持久化并限制权限。完成正式迁移后再执行一轮 `--verify-only`；默认 Compose 命令是 `--resume`，需要其他模式时覆盖 command。

## 8. 日志、监控和告警

最低要求：

- 收集 Gateway、Server、Worker 的 stdout/stderr。
- Docker JSON 日志按 20MB、5 个文件轮转。
- 监控 `/readyz`、HTTP 5xx、Worker 队列积压、发布失败率和 COS 403/404。
- COS 开启访问日志，日志 Bucket 与业务 Bucket 分离。
- 数据库启用自动备份和时间点恢复。
- Redis 根据任务恢复要求启用持久化或使用云托管高可用版本。
- 容器主机监控 CPU、内存、磁盘、inode 和 Docker 异常重启。

## 9. COS 生命周期

`deploy/tencent-cos/lifecycle-plan.example.json` 是人工评审计划，不是直接提交 COS API 的请求。配置前必须由业务确认留存要求：

- 未完成 Multipart 上传建议 7 天终止。
- 人工发布包建议 30 天过期。
- ASR、声音和数字人中间产物可在 30 天后转低频。
- 最终成片和封面至少保留 180 天，实际以合同、隐私和运营规则为准。

开启版本控制后还需单独配置历史版本过期，避免成本无限增长。

## 10. 回滚

准备上一版本四个镜像 digest：

```bash
export PREVIOUS_ORAL_SERVER_IMAGE=registry.example.com/oral/server@sha256:<digest>
export PREVIOUS_ORAL_GATEWAY_IMAGE=registry.example.com/oral/gateway@sha256:<digest>
export PREVIOUS_ORAL_WEB_IMAGE=registry.example.com/oral/web@sha256:<digest>
export PREVIOUS_ORAL_ADMIN_IMAGE=registry.example.com/oral/admin@sha256:<digest>
export ROLLBACK_SCHEMA_COMPATIBLE=true
bash deploy/scripts/rollback.sh /etc/oral/deploy.env
```

回滚脚本不会自动执行 Alembic downgrade。只有经过评审确认旧镜像兼容当前数据库 Schema 后，才允许设置 `ROLLBACK_SCHEMA_COMPATIBLE=true`。脚本会先停止当前 Worker、API 和 Gateway，再同时切换上一版本四个镜像，避免新旧路由与业务版本混用。

需要数据库降级时：

1. 停止 API 和 Worker。
2. 备份数据库。
3. 查明目标 Alembic revision 和 downgrade 影响。
4. 人工执行降级。
5. 启动旧镜像并验证 `/readyz`、余额流水、任务恢复和最小真实链路。

## 11. 上线验收

- `docker compose ... config --quiet` 通过。
- API、Worker、Migration Server image digest 完全相同。
- Gateway、Web、Admin 镜像使用当前 commit 构建并固定 digest。
- Web/Admin 以只读根文件系统实际启动并通过 `/healthz`。
- `/readyz` 返回生产环境、真实 Provider、数据库、Redis、COS 全部就绪。
- 上传视频、生成任务、成片播放和人工发布包跑通。
- Worker 重启后任务可恢复。
- COS 对象能通过 API 签名媒体路径读取。
- 真实发布账号只在完成 staging 验收后加入 `PUBLISH_VERIFIED_PLATFORMS`。
- Server、Worker、Gateway 分别重启一次，无数据丢失、重复扣费或重复发布。

## 12. 明确不自动化的操作

以下操作不会由仓库脚本自动执行：

- 创建或删除 COS Bucket。
- 修改 CAM 用户和策略。
- 修改 COS 生命周期、版本控制或访问日志。
- 删除源 MinIO/S3 对象。
- 自动数据库 downgrade。
- 申请域名、证书或修改腾讯云安全组。

这些操作具有账号级或数据删除风险，必须在腾讯云控制台或经过单独审批的 IaC 流程中完成。
