## 1. 决策

**NO-GO：当前不得启动 S3-02 至 S3-14，不得在生产或灰度环境启用抖音私信模块。**

`IM_ENABLED` 必须保持 `false`。现阶段 07 私信能力只保留为开发、测试环境中的内部技术预研代码，不属于正式 SaaS、客户私有部署或可交付能力。

## 2. 判定依据

### 2.1 第二阶段尚未通过真实验收

- 仓库中没有 `evidence/stage2` 真实验收产物。
- 2026-07-21 执行 `uv run python scripts/stage2_acceptance.py`，因缺少真实账号、资产和链接参数退出，未形成两类输入各三轮成片及真实发布证据。

因此不满足复审版计划第 13 节的第一个启动条件。

### 2.2 当前权威文档禁止相关能力进入商业产品

- `docs/06-最终开发文档.md` 第 2.4 节和第 12.1 节将逆向第三方 App 私有接口定义为商业产品合规红线，仅允许内部技术预研评估。
- `docs/07-抖音私信模块开发任务书.md` 的技术路线依赖私有 WebSocket、签名和逆向协议，尚无平台正式授权或商业合规确认记录。

因此不满足复审版计划第 13 节的第二个启动条件。

### 2.3 授权、数据和部署边界尚未书面确认

当前没有经责任人确认的书面材料覆盖以下事项：

- 账号 Cookie 的授权范围、保管责任和失效处置；
- 私信数据的采集目的、保存期限、删除机制和用户权利；
- 自动回复的默认状态、内容责任、人工接管和紧急停止责任；
- 07 的最终形态是正式 SaaS、客户私有部署还是内部实验。

因此不满足复审版计划第 13 节的第三、第四个启动条件。

## 3. 工程处置

1. Web 路由、导航、API 路由和监听恢复继续由 `IM_ENABLED=false` 默认关闭。
2. 非开发/测试环境一旦设置 `IM_ENABLED=true`，服务启动必须立即失败，并明确报告本 No-Go 门禁。
3. 不引入固定 `.proto`、签名、设备注册、真实收发或自动回复实现；这些工作均属于 S3-02 及以后，不得越过 S3-01。
4. 现有 IM 占位代码不得作为真实能力宣传、演示验收或生产兜底。
