## 第一部分：竞品界面模式分析（布局设计的输入）

从 [01-市场调研报告](01-市场调研报告.md) 提炼竞品的界面组织模式，作为我们 IA 设计的对标与差异化依据。

### 1.1 竞品界面组织模式

| 竞品 | 界面组织模式 | 优点 | 短板（我们的机会） |
| --- | --- | --- | --- |
| 旗博士/茄条/夜神（同源系） | 本地客户端，按流水线模块平铺 Tab：文案提取→仿写→声音→数字人→字幕→发布 | 流程直白、学习成本低 | 工程感强、无任务/资产概念；批量生产能力弱；无数据回流 |
| 罗根 | 8 大模块分步向导（文案→音频→视频→字幕→BGM→标题→封面→发布） | 步骤化、每步参数暴露充分（语速/底边距等） | 单线程操作，无队列视图；纯云端无本地状态感知 |
| 轻语 | 6 大功能中心：形象管理/数字人中心/声音克隆/一键出视频/素材管理/账号发布 | 「资产中心 + 一键出片」双层结构，人设档案贯穿 | 四端但 Web 弱；数据看板缺失 |
| 淘金 AI | Web 端"一键创作"为绝对核心，输入链接 → 批量出 10+ 条 | 批量复刻场景做到极致 | 资产沉淀薄、无本地算力 |
| AIPGPT | 企业级：策划案（81 字段）→ 选题 → 创作 → 知识库 | 策略层 + 知识库壁垒 | 重交付，个人用户不可用 |
| 蝉镜/闪剪（大厂 SaaS） | 数字人库 + 模板驱动的编辑器 | 编辑器体验最好 | 不做爆款复刻与自动发布 |

### 1.2 布局设计结论

**总体形态采用轻语式「左侧功能中心导航 + 中间主体工作区」布局**，明确拒绝罗根/旗博士式"流水线模块平铺 Tab"——平铺布局把生产线暴露为界面骨架，用户每用一次都要走一遍工序；轻语模式的本质是**以资产和功能为中心组织界面，流水线被收进"一键出片"一个入口里**。我们在此基础上重新排版，强化三点：

1. **一键成片是左栏唯一高亮 CTA**（对标轻语"一键出视频" + 淘金"输入链接批量出片"），点击进入中间主体的向导工作区：默认全自动跑完，每步可展开人工微调（F-405"单步可干预"）；
2. **左栏按「创作 / 资产 / 分发」三段分组**（轻语 6 大模块的重排与扩充），人设/IP 切换器置顶——任何页面都能一键切换当前操作的 IP（轻语"形象管理解决账号精神分裂"的强化）；
3. **任务中心独立成项**（轻语没有，是"矩阵生产工具"与"单条玩具"的分水岭）：批量 F-406、定时 F-722、失败重试、进度实时可见。

全局还有两个**常驻能力**（竞品均没有，属于差异化）：
- **算力与额度指示器**（左栏底部常驻卡）：云端额度余额 + 当前算力通道。**算力策略定为「云端为主，本地备用」**——默认全部任务走云端 GPU，本地引擎作为可选增强节点（见第五部分调度设计），界面只暴露"云端/本地"状态，不要求用户理解算力细节；
- **合规盾牌**：文案去重度分（F-106）、违规预检（F-711）结果在生成流程中内联展示。

**设计要点**：

- **IP 切换器置顶**是轻语"人设档案"思想的升维：切换后，工作台数据、一键成片默认配置、资产列表、任务列表全部按 IP 过滤，天然支撑多 IP 矩阵（F-721）；
- 导航分组（创作/资产/分发）对应用户心智模型"**做内容 → 养资产 → 发出去**"，比罗根 8 模块平铺少一层认知负担；
- 左栏底部状态卡常驻额度与算力通道，回应"算力/续费透明"差异化主张；
- 收纳态（72px）只留图标 + CTA，中间主体最大化。
- **一级导航精简为 7 项**（v1.1 效果图迭代确认）：数字人中心/声音中心/模板中心不再占一级位，收敛为资产页内「IP 资产」Tab 条二级导航（见 3.8）；账号管理收敛为发布管理页内入口（平台账号卡 + 「账号管理 →」）；「我的账号」唯一入口为顶栏右侧头像；「设置」入口收进算力卡标题行 ⚙，左栏不再设 side-foot。

## 第三部分：核心页面布局（线框详设）

视觉基调（全端统一）：**深色高端 SaaS 风**——深空灰渐变底色（`#0B0E14 → #111827`）、玻璃拟态卡片（毛玻璃 + 1px 半透明描边）、大量留白、单一品牌强调色（建议青紫渐变 `#6366F1 → #22D3EE`）用于主行动按钮与流水线进度、微动效（卡片悬浮抬升、步骤切换的 slide-fade、任务进度的 shimmer）。移动端浅色/深色双主题，深色优先。

### 3.4 IP 资产中心

- **IP 档案页** `/assets/personas/:id`：左侧 IP 基本信息卡（头像/领域/平台账号绑定），右侧分 Tab：人设定义（口吻/价值观/禁忌词表单，F-701）→ 绑定资产（数字人/声音/模板 chips）→ 内容统计。人设表单支持「AI 生成人设」——输入一段话描述，LLM 结构化填充。
- **数字人库**：卡片网格 + 状态徽标（训练中/可用/失败）；训练页为 3 步向导（上传视频 → 授权确认勾选 → 训练进度），**强制本人授权校验**（合规要求，F-301 安全条款）。
- **声音库**：与数字人同构；克隆向导（录音/上传 → 授权 → 克隆进度 ≤10min）+ 试听对比（原声 vs 克隆）。
- **素材库**：瀑布流 + 语义标签筛选（F-703 自动打标结果可编辑）。
- **模板中心**：行业模板分组（口播/带货/知识/本地生活），卡片预览动图，「使用模板」直接带入一键成片第⑤步。

### 3.5 发布模块

- **账号管理**：平台分组卡片（抖音/视频号/小红书/快手），每个账号卡显示头像、登录态（绿/红）、失效时间；「添加账号」走二维码扫码授权弹窗；**登录态失效红色横幅 + 一键重新授权**（F-502 失效提醒）。

## 第四部分：前端技术栈选型

### 4.1 选型约束（来自需求与竞品分析）

1. **五端协同**（F-731/732）：Win/Mac 客户端 + iOS/Android + Web，且差异化主张要求全端覆盖对齐轻语；
2. **云端为主、本地备用**：算力任务默认全部走云端 API，Web 即主端；桌面端只需**预留**本地引擎接入能力（sidecar 桥接、GPU 探测），不作为默认分发形态；
3. **团队效率**：小团队不可能维护 5 套代码，必须**一套核心代码库 + Monorepo 复用**；
4. **开发体验**：热更新、强类型、组件生态成熟。

### 4.2 跨端方案对比

| 方案 | 覆盖端 | 代码复用 | 本地引擎预留能力 | 生态成熟度 | 结论 |
| --- | --- | --- | --- | --- | --- |
| A. Flutter 全端 | 四端 + Web(弱) | 一套 Dart | 需 FFI/平台通道，桌面端插件较少 | 移动端★★★★★ 桌面★★★ | ❌ 前端团队技术栈切换成本高，Web 端体验弱 |
| B. Electron + RN + Next.js | 全端 | 三套壳、部分共享 | Electron 成熟 | ★★★★★ | ❌ Electron 包体大内存高；三套壳维护重 |
| **C. Tauri 2 + React（Web/桌面）+ Expo RN（移动）** | 全端 | Monorepo 共享业务层 70%+ | **Tauri 预留 sidecar 机制**，随时可接入本地引擎 | ★★★★ | ✅ **推荐** |
| D. 纯 Web（PWA） | 全端(弱) | 一套 | ❌ 无法扩展本地引擎 | ★★★★★ | ❌ 丢失"本地备用"预留能力，未来无法回补混合算力 |

**推荐方案 C 的理由**：

- **Web 为主端**：所有功能以云端 API 驱动，浏览器打开即用（对齐淘金 AI 的零门槛，但我们同时有客户端）；
- **Tauri 2 桌面端 = Web 套壳 + 能力预留**：安装包 ~10MB（Electron 的 1/10）；默认不捆绑本地引擎，但 `sidecar` 机制与 Rust 后端（GPU 探测、文件加密）随时可用，**本地引擎后续以"可选下载组件"形式接入，用户无感知升级**；
- **React 一处学习三处编写**：Web 与桌面共用同一套 React 应用；移动端 Expo RN 复用 API Client、类型定义、状态逻辑、设计令牌；
- **Expo（React Native）**：推送（F-734 通知中心）、相册/分享、扫码授权（F-502）等移动能力开箱即用；OTA 更新绕过商店审核发小版本。

### 5.2 架构决策说明

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 单体 vs 微服务 | **模块化单体起步** | MVP 团队小、链路强耦合（流水线跨所有模块）；模块边界按微服务标准划分（独立包、独立路由、禁跨模块直连私有表），V2.0 按需拆出 publish/pipeline |
| 语言栈 | **Python 全栈**（FastAPI + Worker） | AI 生态全在 Python（faster-whisper/CosyVoice/FFmpeg 编排/MoviePy/飞影 SDK 自封装）；一人可写全链路，无跨语言序列化成本；竞品（旗博士/罗根/MoneyPrinterTurbo）同为 Python |
| 业务框架 | FastAPI + Pydantic v2 + SQLAlchemy 2 (async) + Alembic | 自动 OpenAPI（供前端生成类型）、异步 IO、生态标准 |
| 任务队列 | **Dramatiq + Redis**（不用 Celery） | API 更现代、原生延时/优先级/重试，任务量量级（单用户日几十~几百条）Redis 足够；定时任务用 APScheduler |
| 实时进度 | WebSocket 网关（同一 FastAPI 进程）+ Redis Pub/Sub 桥接 Worker 进度事件 | 任务进度秒级推送到五端 |
| 本地 Agent（备用通道） | 与云端 Worker **同一份代码**，PyInstaller 包作为应用内「可选下载组件」接入 | **云端为主、本地备用**：默认全任务走云端；本地引擎是高配用户的免额度通道与离线卖点，V1.5+ 开放 |
| 存储 | PG + Redis + MinIO | MinIO 私有部署起步，云上环境切 S3/OSS 兼容协议零改动 |
| 认证授权 | JWT 双令牌 + 设备绑定 + License 签发（买断） | F-601/602：5 端登录同步 + 买断授权 + 云额度并行 |

### 6.2 Provider 抽象层（对应 03 报告的 VoiceProvider/AvatarProvider 决策）

```python
# packages/providers/src/providers/base.py
from typing import Protocol, AsyncIterator
from pydantic import BaseModel

class SynthesizeResult(BaseModel):
    audio_url: str
    duration_ms: int
    word_timestamps: list[dict]      # 字级时间戳 → F-401 字幕双模式首选

class VoiceProvider(Protocol):
    name: str
    async def clone(self, sample_url: str, consent_token: str) -> str: ...   # → voice_id
    async def synthesize(self, text: str, voice_id: str, *, speed: float = 1.0,
                         emotion: str | None = None) -> SynthesizeResult: ...
    async def list_voices(self, owner_id: str) -> list[dict]: ...

class AvatarProvider(Protocol):
    name: str
    async def clone_by_video(self, video_url: str, consent_token: str) -> str: ...  # → avatar_id
    async def create_by_audio(self, avatar_id: str, audio_url: str,
                              *, resolution: str = "1080p") -> str: ...        # → task_id
    async def query_task(self, task_id: str) -> "AvatarTaskStatus": ...
    async def list_public(self) -> list[dict]: ...

class LLMProvider(Protocol):
    async def rewrite(self, src_text: str, persona: dict, strength: int,
                      instruction: str | None) -> str: ...
    async def generate_topics(self, keywords: list[str], n: int = 5) -> list[dict]: ...
    async def check_similarity(self, a: str, b: str) -> "DupReport": ...  # 0-100 分+重复片段
```

- `consent_token`：声音/形象克隆强制传入本人授权凭证（合规红线，克隆前活体/授权校验结果），所有实现必须校验。
- `registry.py` 按「用户配置 → 租户默认 → 系统默认」三级解析实现，例如 `voice.primary=minimax, voice.fallback=cosyvoice_local`，主实现异常自动降级并记事件。
- 新增供应商 = 新建一个文件实现 Protocol + 注册一行，**零改动业务代码**。

### 6.3 流水线引擎核心模型（pipeline 模块）

```python
# packages/modules/src/modules/pipeline/engine.py（骨架）
STEP_ORDER = ["parse", "asr", "rewrite", "voice", "avatar", "compose", "edit", "publish"]
# UI 7 步映射: 链接/选题(parse+asr) → 文案(rewrite) → 声音(voice) → 数字人(avatar)
#              → 合成(compose) → 剪辑(edit, 自动模式可跳过) → 发布(publish)

class PipelineEngine:
    """状态机驱动: 每步产出物写入 ctx.artifacts, 支持单步重跑/人工改稿后继续"""
    async def run(self, pipeline_id: str) -> None:
        ctx = await self.load_context(pipeline_id)          # 含 IP 人设/配置/产物
        for step_name in STEP_ORDER[ctx.cursor:]:
            step = self.steps[step_name]
            await self.emit(step_name, "running")           # → WS 推送前端进度条
            route = await compute_router.pick(step_name, ctx)  # 本地 or 云端
            try:
                result = await step.run(ctx, route=route)
            except StepRecoverableError as e:                # 供应商失败→降级实现
                result = await step.run(ctx, route=route, provider=e.fallback)
            ctx.artifacts[step_name] = result.output
            await self.emit(step_name, "done", result.metrics) # 含 quota 扣减事件
            await self.save(ctx)
            if ctx.mode == "manual" and step_name != "publish":
                await self.pause(ctx)                        # 可干预模式: 暂停等待用户确认
```

### 6.4 算力调度器（ComputeRouter：云端为主 · 本地备用）

```
默认策略 CLOUD_FIRST: 任务到达 → 云端 GPU Worker 池(默认通道, 按步骤扣额度)
  ├─ 用户已接入本地引擎(可选): Agent 心跳在线且 capabilities 覆盖该步骤 → 路由本地(免扣额度)
  │    调度: 云端经 WS/轮询把任务参数下发给 sidecar,
  │    sidecar 执行同一 Worker 代码, 产物直传 S3, 进度回传
  ├─ 本地未接入/离线/步骤不支持 → 自动回落云端, 用户无感知
  │    云端排队超阈值时可引导用户「接入本地引擎加速」
  └─ 批量任务: 每步独立路由 → 异构混跑(本地跑ASR+合成, 云端跑数字人)
```

- 路由优先级：`用户显式选择 > 本地 Agent 可用性 > 云端默认`；云端是永远生效的兑底通道。
- 心跳协议（本地引擎接入后启用）：`{agent_id, gpu: {model, vram_mb, free_mb}, caps: ["asr","tts","compose"], load: 0-1, version}`，30s 周期，90s 无心跳判离线自动切云。
- 额度价格表存 PG（`quota_price: step × resolution × unit_price`），计费明细 F-602 由此产生。

## 附：一页纸结论

- **页面布局**：轻语式「左侧功能中心导航 + 中间主体工作区」——左栏 IP 切换器置顶 + 一键成片唯一高亮 CTA + 创作/资产/分发三段分组 + 底部算力额度常驻卡；中间主体为向导/工作台/表格工作区。拒绝流水线平铺 Tab。
- **前端脚手架**：`pnpm + Turborepo` Monorepo —— Vite+React（**Web 主端**）/ Tauri 2 壳（桌面，预留 sidecar）/ Expo RN（移动），共享 api-client/types/ui/hooks/platform 五个包，`PlatformBridge` 抽象抹平端差异。
- **后端脚手架**：`uv` workspace —— FastAPI 模块化单体 + Dramatiq 队列 + Provider 抽象层（七类可插拔）+ ComputeRouter **云端为主、本地备用**：默认全任务走云端 GPU 池扣额度，本地引擎作为可选下载组件 V1.5+ 开放，云端/本地同一份 Worker 代码保证随时可切换。
