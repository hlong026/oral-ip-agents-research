# 双端、套餐 SKU 与积分接口

## 权限边界

- 用户 Token：`role=user`，`aud=user`，仅访问 `/api/v1/*`。
- 管理员 Token：`role=admin`，`aud=admin`，仅访问 `/api/admin/v1/*`。
- 开放注册已关闭；新用户通过激活码开户。
- Provider 密钥、地址、启停及成本仅属于管理控制面。用户接口和前端构建不得包含密钥值。

## 用户接口

| 方法 | 路径                                        | 用途                           |
| ---- | ------------------------------------------- | ------------------------------ |
| GET  | `/api/v1/catalog/plans`                     | 获取当前生效的公开套餐         |
| GET  | `/api/v1/catalog/module-prices`             | 获取当前生效的公开模块积分价格 |
| POST | `/api/v1/billing/price-preview`             | 创建 10 分钟有效的报价快照     |
| POST | `/api/v1/billing/reservations`              | 按报价原子冻结积分             |
| POST | `/api/v1/billing/reservations/{id}/release` | 幂等释放冻结积分               |
| GET  | `/api/v1/billing/balance`                   | 查询积分余额                   |
| GET  | `/api/v1/billing/usage`                     | 查询消费明细                   |
| POST | `/api/v1/activation/activate`               | 激活码开户                     |
| POST | `/api/v1/activation/redeem`                 | 登录后续费或兑换积分包         |
| GET  | `/api/v1/subscription`                      | 查询当前套餐和有效期           |

生产环境创建流水线任务必须提交有效 `quoteId`。创建任务时冻结预计积分；任务完成后结算，取消或失败时幂等释放。报价保存具体价格版本和项目明细，不受之后调价影响。链接或选题任务按用户 IP 人设的目标视频时长估算，缺少人设时使用 60 秒保守值，禁止空文案退化为 1 秒报价。

独立调用选题生成、文案生成/相似度检测、ASR、TTS、声音克隆和数字分身训练时，用户端也会先展示当前报价。接口必须携带与模块、计费单位及原始用量完全匹配的一次性 `quoteId`；后端在 Provider 调用前冻结积分，成功后按具体模块写入用量，异常时恢复原积分批次。按时长计费的本地上传由浏览器预读、后端 `ffprobe` 复核；按时长计费的链接解析第一版只接受可验证的 60 秒以内媒体，无法确认时长则在 ASR 前拒绝。这样不能通过文案工坊或素材中心绕过流水线计费。

声音克隆和数字分身训练是异步任务，冻结记录会绑定到素材记录：Provider 返回最终成功后才结算，最终失败时释放；仅“任务已提交”不会提前扣成已消费。各模块只允许与实际输入可验证的计费单位，例如 TTS 不允许按音频秒数配置、声音克隆只允许按次或按资产配置。

积分以 `credit_grants` 批次为余额依据，只消费尚未过期的积分，并优先扣减最早到期批次。冻结记录保存批次分配快照，释放时恢复原批次；`quota_accounts.balance` 只是加速汇总值。包年套餐激活时发放首月积分，之后按 30 天周期幂等补发，最多发到套餐到期日。消费完成后同时写不可变积分流水和用户用量明细。

## 管理接口

| 方法     | 路径                                                 | 用途                        |
| -------- | ---------------------------------------------------- | --------------------------- |
| POST/GET | `/api/admin/v1/plans`                                | 创建草稿、查询套餐版本      |
| POST     | `/api/admin/v1/plans/{id}/clone`                     | 从已售版本克隆新草稿        |
| POST     | `/api/admin/v1/plans/{id}/publish`                   | 立即或定时发布              |
| POST     | `/api/admin/v1/plans/{id}/retire`                    | 停止销售                    |
| POST/GET | `/api/admin/v1/price-versions`                       | 创建、查询价格版本          |
| PUT      | `/api/admin/v1/price-versions/{id}/modules/{module}` | 配置固定模块价格            |
| POST     | `/api/admin/v1/price-versions/{id}/publish`          | 立即或定时发布价格          |
| POST     | `/api/admin/v1/activation/batches`                   | 按已发布 SKU 版本生成激活码 |
| GET/PUT  | `/api/admin/v1/providers`                            | 管理加密的 Provider 配置    |
| GET      | `/api/admin/v1/users`                                | 用户管理                    |
| POST     | `/api/admin/v1/users/{id}/credits/adjust`            | 带原因的人工积分调整        |
| GET      | `/api/admin/v1/cost-analysis`                        | 积分与成本汇总              |
| GET      | `/api/admin/v1/audit`                                | 管理操作审计                |

套餐和价格版本采用 `draft → scheduled/published → retired` 生命周期。已发布经济字段不可修改；必须克隆或创建新版本。激活码只保存 SKU 版本引用，明文码只在创建批次时返回一次，数据库保存 HMAC 哈希。人工积分调整只追加 grant/ledger 和审计记录，不提供直接修改余额的接口。

Provider 开关在实际调用时再次校验。管理员关闭真实 Provider 后，注册表会跳过该实现；链接解析的 Douyidou 直连和降级链使用同一开关，不能绕过管理控制面。生产中的旧任务若没有积分冻结记录会直接失败，避免继续走旧聚合余额扣费路径。

## 上线步骤

1. 配置生产密钥、数据库和 Redis。
2. 执行 `cd server && alembic upgrade head`。
3. 首次启动创建管理员，并删除引导密码环境变量。
4. 登录管理端检查 `legacy-v1` 价格目录，按实际计费单位发布新版本。
5. 创建并发布套餐 SKU，再基于其具体版本生成激活码。
6. 配置 Provider 并确认健康状态后，开放用户端。

回滚数据库结构使用 `alembic downgrade f0a1b2c3d4e5`。生产回滚前须先停止新任务，避免丢失新版本产生的报价、冻结和积分流水。
