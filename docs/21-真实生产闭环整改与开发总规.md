## 1. 文档地位

本文件是本轮整改与开发的唯一执行规格。

`docs/10`、`docs/11`、`docs/12`、`docs/13`、`docs/17`、`docs/18`、`docs/20` 和各类总结报告仅作为历史设计、验收线索和决策证据；当它们与当前代码、当前测试或本文件冲突时，以当前代码事实和本文件为准。

本轮不以“页面存在”“接口返回 200”或“Mock 测试通过”作为业务完成依据。

## 2. 真实需求

项目要交付的不是一组互相独立的模块，而是一条可以重复运行、失败可恢复、费用可核对、结果可追踪的口播视频生产链：

```text
真实素材
→ 解析/ASR
→ 文案生成
→ 声音/TTS
→ 数字人口播
→ 视频合成
→ 编辑定稿
→ 不可变发布快照
→ 对象存储
→ 平台发布或人工发布包
→ 结果记录
→ 积分结算与审计
```

## 3. 完成状态定义

每项能力必须分别记录三个状态，禁止混用：

1. `IMPLEMENTED`：代码和迁移存在。
2. `LOCALLY_VERIFIED`：当前 checkout 的自动化测试、静态检查、构建或本地运行证据通过。
3. `EXTERNALLY_ACCEPTED`：使用真实 Provider、真实平台账号、真实存储或真实签名证书完成验收，并保存脱敏证据。

只有 `EXTERNALLY_ACCEPTED` 可以计入真实业务完成度。缺少外部账号、凭据、企业审批、签名证书或生产环境时，必须标记为 `EXTERNAL_BLOCKED`，不能用 Mock 结果替代。

## 4. 执行原则

- 先恢复绿色主干，再扩展功能。
- 以纵向业务闭环为开发单位，不按目录横向宣布模块完成。
- 新功能和缺陷修复均先写失败测试。
- 使用现有状态机、存储和错误处理模式，不增加无必要依赖。
- 一个逻辑变更一个提交，提交必须可独立回退。
- 真实平台失败必须保留人工发布包兜底。
- IM 在合规、状态机和灰度证据完成前保持 fail-closed 或只读。
- 上一阶段未通过全部硬门禁，不进入下一阶段。

### 7.2 自动化验收

- local/S3 存储契约测试。

- 定稿快照不可绕过测试。
- 发布幂等和重复提交测试。
- Provider 超时、未知结果和 reconciliation 测试。
- 积分冻结、结算、释放和重复回调测试。

### 7.3 外部验收

真实验收必须保存以下脱敏证据：

- 时间、环境、commit SHA。
- Provider 名称与真实请求 trace ID。
- 输入素材 hash、定稿 revision ID、输出视频 hash。
- 发布账号脱敏 ID、publish job ID。
- 平台返回状态；无法取得真实作品 ID 时明确 `internal`。
- 积分冻结、结算或释放记录。
- 失败样例、恢复动作和最终结果。

阶段三只有在同一 commit 上连续完成三次真实成功、一次失败恢复和一次重复提交验证后，才能标记 `EXTERNALLY_ACCEPTED`。

## 9. 阶段五：IM、桌面分发与扩展边界

### 9.1 IM

短期路线固定为：

- 监听聚合可以灰度。
- 服务端主动发送保持 fail-closed。
- 人工回复通过受控桌面 WebView 打开官方页面。
- 未取得官方 API 审批前，不恢复逆向自动发送。

任务：

| ID | 任务 | 验收 |
| --- | --- | --- |
| G5-01 | IM 状态机和 lease 回归 | 多 Worker 不重复监听，故障恢复可解释 |
| G5-02 | 多账号 WebView session 隔离 | 账号之间不串 Cookie/登录态 |
| G5-03 | 清理不可用发送残留 | API、前端和文档不再暗示服务端可发送 |
| G5-04 | Kill switch 与灰度名单 | 关闭后不产生新监听或发送行为 |
| G5-05 | 七天灰度证据 | 重连、去重、积压、Cookie 失效和人工恢复可审计 |

### 9.2 桌面分发

| ID | 任务 | 验收 |

| G5-06 | macOS 构建门禁 | HTTPS API、签名、公证、安装和启动 smoke |

### 9.3 后续扩展

素材库、模板、数据分析、团队协作、移动端和自动更新不在核心生产链之前开发。它们必须分别补产品规格、数据边界和验收标准后再进入实施，不因已有隐藏路由或预览页面而计入完成度。

## 10. 测试策略

### 10.1 测试层级

- 单元测试：纯状态转换、报价、限流、路径校验、错误分类。
- 集成测试：数据库、队列、存储、Provider 适配器、积分状态机。
- 契约测试：OpenAPI、Provider 请求响应、发布驱动输入。
- E2E：用户纵向链和管理员恢复链。
- 外部验收：真实 Provider、真实账号、真实桌面签名分发。

### 10.2 不允许的替代关系

- 单元测试通过不能替代 typecheck/build。
- Mock Provider 通过不能替代真实 Provider。
- 页面可达不能替代业务 E2E。
- 本地 Tauri 启动不能替代签名安装包。
- 内部 post ID 不能替代平台作品 ID。
- 文档勾选不能替代当前 checkout 的验证输出。

## 11. 提交与回退

- 阶段二使用 `fix/*` 逻辑提交。
- 阶段三至五按独立业务增量提交。
- 每次提交包含中文意图、验证证据和已知缺口。
- 数据库迁移单独提交，并提供明确 downgrade。
- 外部凭据、Cookie、二维码、账号标识和真实视频不得提交。

## 12. 当前停止条件

遇到以下条件时，只停止对应外部验收，不停止可继续的本地工程工作：

- 缺真实 Provider 凭据。
- 缺平台账号或企业审批。
- 缺 macOS/Windows 签名证书。
- 缺生产 S3/Redis/PostgreSQL 环境。

阻断项必须记录为 `EXTERNAL_BLOCKED`，附所需输入和恢复入口。
